# WristMatch database design

## Database conventions

Database: SQL Server.

All identifiers are `uniqueidentifier` values generated by the application. Dates are stored as `datetimeoffset` in UTC. Money uses `decimal(18,2)` and every amount carries a three-character ISO currency code. Soft-deletable records retain their audit history. Private media never appears in public catalogue tables or public static storage.

## Identity and administration

ASP.NET Core Identity remains the credential authority. The application adds domain fields and administration records around the standard Identity tables.

### AspNetUsers

| Column | Type | Rules |
|---|---|---|
| Id | nvarchar(450) | Primary key from Identity |
| UserName | nvarchar(256) | Unique, normalized |
| Email | nvarchar(256) | Unique, normalized |
| DisplayName | nvarchar(120) | Required |
| IsActive | bit | Required, default 1 |
| LastLoginAt | datetimeoffset | Nullable |
| CreatedAt | datetimeoffset | Required |
| UpdatedAt | datetimeoffset | Required |
| RowVersion | rowversion | Concurrency guard |

Identity supplies password hashes, lockout, security stamp, email confirmation, and two-factor fields. Passwords and provider keys are never stored in domain tables.

### AspNetRoles / AspNetUserRoles

Standard Identity role and membership tables. Initial roles are `SuperAdmin`, `CatalogManager`, `OperationsViewer`, and `SupportViewer`. Authorization uses policies rather than role names directly in controllers.

### AdminLoginEvents

| Column | Type | Rules |
|---|---|---|
| Id | uniqueidentifier | Primary key |
| UserId | nvarchar(450) | Nullable FK to AspNetUsers |
| EmailAttempt | nvarchar(256) | Normalized, never a password |
| Succeeded | bit | Required |

| IpAddressHash | varbinary(32) | Hashed for throttling and audit |
| UserAgentHash | varbinary(32) | Hashed |

Indexes: `OccurredAt`, `EmailAttempt + OccurredAt`, and `UserId + OccurredAt`.

|---|---|---|

| SessionId | uniqueidentifier | Required FK |

| State | int | Queued, Preparing, Submitted, Processing, Succeeded, Failed, Expired, Cancelled |
| IdempotencyKey | nvarchar(160) | Required |
| RequestHash | varbinary(32) | Required |
| ProviderTaskId | nvarchar(200) | Nullable |
| ProviderSubmissionState | int | NotStarted, Submitted, Ambiguous |
| ErrorCode | nvarchar(100) | Nullable |

| UpdatedAt | datetimeoffset | Required |
| DeadlineAt | datetimeoffset | Required |

The provider task id is persisted immediately after a successful provider submission. Task creation is never blindly retried after an ambiguous network result.

## Relationships

- One admin user creates or updates many products, assets, licences, and audit events.
- One guest session owns many photos and try-on jobs.
- One photo can be referenced by many try-on jobs until it expires or is deleted.
- One product is referenced by many jobs and cannot be hard-deleted once referenced; archive instead.
- One try-on job has zero or one result.
- One try-on job has many provider request events.
- All private media is inaccessible without an active owning guest session or a permitted admin operation; admin catalogue access never grants access to shopper media.

## Migration order

1. Identity and administration tables.
2. Catalogue, occasions, assets, and licence tables.
3. Guest sessions and private photo assets.
4. Try-on jobs, results, and provider events.
5. Rate-limit buckets and operational indexes.

## Application modules

- Public shopper: home, catalogue, product details, studio, compare, favourites, privacy.
- Admin: login, dashboard, products, product assets, users, roles, audit log, job health.
- Background processing: lease acquisition, provider preparation, submission, polling, expiry, cleanup, reconciliation.

## Security decisions

- No mandatory shopper account in MVP.
- Admin authentication uses ASP.NET Core Identity and secure HttpOnly cookies.
- Mutating admin requests require antiforgery validation.
- Guest tokens are opaque, random, cookie-bound, and hashed at rest.
- All private image endpoints use ownership checks and `Cache-Control: no-store`.
- Admin audit entries contain safe metadata only.
- Provider credentials are environment or secret-manager configuration only.
